# Stadium games

Plan and decisions: `GAMES.md` in the repo root.

## Layout
- `registry.js` lists every game. Each game is `<id>/rules.js` (pure JS: `meta`, `setup`, `turn`, `move`, `view`, `over`, `timeout`, optional `delay`, and `bot` for Chitbots) plus `<id>/ui.jsx` (your hand, banner text, the flat-table centre).
- `rng.js` is the seeded RNG every rules module uses.
- `useGame.js` holds the feature flag (`GAMES_ON`), the live table hook and the call to the referee.
- `GameScreen.jsx` is the lobby, HUD and hand overlay (lazy). `Table3D.jsx` is the three.js table (its own lazy chunk). `People.jsx` puts the real `<Avatar>`s at the seats.
- Server: `supabase/functions/_shared/referee.ts` (the referee), one tiny `supabase/functions/game-<id>/index.ts` per game, and `supabase/migrations/036_games.sql` (tables, RLS, RPCs).

## One source of truth: redeploy after any rules change
Each game has its own edge function, `game-<id>`, whose `index.ts` is just `serveReferee({ <id>: rules })` from `_shared/referee.ts`, so it runs these exact files and bundles only that game. The browser calls `game-${id}` (`callGame` in useGame.js). After changing a game's files under `src/games/<id>/`, redeploy that game's function; after changing `_shared/referee.ts`, `rng.js` or `away.js`, redeploy all of them. Keep the repo paths as file names:

- `node scripts/fnfiles.mjs <id>` prints the function's import closure: its `index.ts`, `_shared/referee.ts`, `rng.js`, `away.js` and every file that game's rules import (poker pulls in highcard, starchat its minis, and so on).
- Supabase MCP `deploy_edge_function`, project `nilludyavkfqwastghmw`, name `game-<id>`, `verify_jwt: true`, `entrypoint_path: "supabase/functions/game-<id>/index.ts"`, and `files`: exactly those paths, contents read from disk. Each deploy is small (about 20 to 70 KB) and stays that way as games are added.
- Or with the CLI from the repo root: `supabase functions deploy game-<id> --project-ref nilludyavkfqwastghmw`.
- `supabase/functions/game/index.ts` is the old all-games function (`serveReferee(GAMES)` with the whole registry). It's a fallback only and is too big to deploy through the MCP; `node scripts/fnfiles.mjs` with no id lists its files.

## Leaving a game (`quit`, `away.js`)
Seated players get **Leave game** in the shared tools bar (also in full view), with a confirm. The referee's `quit` works in any state (`away.js` `quitPlan`, tested in `away.test.js`):
- Lobby or between rounds: same as `stand`.
- Mid-round: the seat and pid stay (every game's state is keyed by pids, so nothing is renamed) and the uid goes into `games.opts.away` (public, so clients know). In a game with Chitbots, `tick` plays an away person's turns with `R.bot` at Normal from their own view, private hand included (`game_private` keeps it), on the bot's quick clock; quitting on your own turn pulls the deadline in. With `meta.noBots` (Chatterflies) their run just times out to 0 m. Real-time games only hand the stand-in what `turn()` names (Chitchen votes, clock ticks), so their drawing or chores lapse. The referee refuses `move` from an away person. When the round ends (`status: 'done'`), away seats are given up and the list cleared (`settleAway`), so they can sit again next round. `start` never passes `away` to `setup`.
- A host who quits hands the table to the first other present person in seat order (`game_save` can't change `host_id`, so the referee updates `games` directly). If no present person would be left seated (Chitbots and away people don't count), the table closes.
After leaving, `Voice.jsx` hides the table for you ("Show the game" brings it back); spectators get the same with **Back to stadium** in the tools bar. Away people are drawn faded at the table and walk back to the crowd.

## Chatterflies (flyer/): a real-time game in a turn-based referee
Everyone flies at once, so the referee only judges the start and each landing. `course.js` is the pure tunnel generator and 60 Hz sim (same input log, same run, on every engine: no Math.sin/sqrt in anything that decides a hit), `pilot.js` the look-ahead search (tests prove every chunk is flyable) and the Chitbot pilots, `rules.js` the referee: bots' runs are flown from the seed when their "turn" comes just after the start, people post `{ type: 'run', ticks, log }` whenever they bonk and the referee replays the log (a few ms) and keeps the replayed distance. The timeout lands someone who vanished on 0 m. The UI brings its own full-screen `Stage` (GameScreen skips the 3D table for any UI module that exports one). Ghosts go over the private realtime topic `fly:<stadium id>`, which needs `supabase/migrations/037_flyer_ghosts.sql` applied. Real tables are people only: `meta.noBots` hides the bot controls and the referee refuses the `bot` action (the Chitbot pilots stay for tests and the lab). Play it locally: `#/table?g=flyer&n=4` (`&auto=1` lets a bot fly for you, `&veh=trotter|brolly|flip|cup|rocket|sponge`, `&tok=3` brew tokens, `&opts=whistle,flock`, `&lab=podium`).

Everything that can end a run lives in the sim, so it replays: yarn, strand gates (sliding further in), steam, yarn looms (charge, then snap tight), cranes (homing volleys further in), six vehicles, the Second Brew spin (brew tokens pull reels at a bonk; three teapots revive you, the reels come from the seed and the tick), missions (three per round from the seed; the referee's replay says which you finished) and the Flock rule's rescue bubbles. A rescue is the one input that comes from someone else: the revived flyer's log names the tick and the rescuer, and the referee checks the rescuer's own replay (people's logs are kept in `secret` under the Flock rule; Chitbots are re-flown from the seed) really touched the bubble near that tick, else it replays the run without the rescue. New drawing goes in `flyer/extras.js` (render.js only hands new vehicles over).

A new game: add `<id>/rules.js` + `<id>/ui.jsx`, list it in `registry.js`, `GAME_INFO` (useGame.js) and `UIS` (GameScreen.jsx), add a scene in `Table3D.jsx`, add `supabase/functions/game-<id>/index.ts` (copy another game's), then deploy `game-<id>`. `npm test` runs every bot through whole games of every registered rules module.

## Pillow Chit Fight (pillow/): drawings, battle cries, live votes
Real-time like Midnight Chitchen (`pub.clock`, `turn()` = the next due Chitbot vote or a clock keeper). Each round: everyone without a defending champion draws one for their pair's prompt (`ink.js`: strokes on a 256 grid packed into base64, capped at 150 strokes / 1,800 points, kept in the secret until the drawing phase ends, then in `pub`), records a battle cry, and the bouts play one by one (lines → vote → win). Winners defend next round on a new prompt; an odd one out faces a House champion from the Chitbots' doodle stash (`doodles.js`). Cries are baked in the browser (`filters.js` builds the same Web Audio chain for the live preview and the OfflineAudioContext bake) into a 16 kHz WAV and uploaded to the private `battle-cries` bucket at `<game id>/<owner>/<round>.wav` (`supabase/migrations/040_pillow_cries.sql`); the referee (`game-pillow`) deletes a table's clips on close / new game and sweeps orphans. Two people can play (`meta.min` 2); Chitbots fill small tables: they hand in their own spin on a stash doodle (`varyArt`: mirrored, scaled, tilted, recoloured), shout a random line from `cries.js`, and vote, so every bout gets real votes. Champions without a recording (bots, House, no-mic players, who may type a line) have `cry.text`, which the browser speaks with `speechSynthesis` at a random pitch and rate (following the output volume), falling back to the squeak. Lab: `#/table?g=pillow&n=4` (`&lab=voice|battle|vote|win|recap|podium`, `&opts=quick`).

## Real-time games (Midnight Chitchen, `chitchen/`)
`meta.realtime` games keep a game clock in `pub.clock`. The referee stamps setup (`opts.now`) and every move and tick with `now: Date.now()`, and skips the stale-version 409 for their moves (`game_save` still refuses a racing write). `turn()` names whoever has the next pending decision (a due Chitbot, a bot still to vote, else a clock keeper who can only send the `tick` timeout), and `delay()` is the time to the next scheduled event. Without `now` (tests) a tick jumps to the next event, so bots play whole nights in milliseconds. Closing a table (`leave`): the host, a server admin/mod (`has_perm` manage_channels or manage_messages), or anyone after 10 idle minutes, in any state. `meta.devOnly` keeps the referee from opening a table for it until it ships. Hidden information: `games.pub` is readable by everyone in the stadium, so Chitchen keeps people's last reported positions and meeting votes in `secret` (only `pub.voted`, the I-voted list, is public until the count), and where each bot is heading in the bot's priv. Bot walk plans stay public because every client draws bots from them; clients only show what is inside your vision (fog of war, walls block sight).

## Starchat (starchat/): party board game
`data.js` holds every name and number (Lantern Hollow, spaces, items, mishaps, Tea House wheel, bonus stars, minigames), `rules.js` the mechanics. The board is Table3D's `StarchatScene` (an outdoor layout: no room or table, everyone walks the lantern path as their own cut-out; `geom.js` lays the board out, `boardArt.js` paints the meadow), the HUD is `hud.jsx` + `hud.css` (news lines from `news.js`, icons in `icons.js`, phones get a ticket strip and a bottom sheet), and the minigame Stage is mounted from the HUD. Lab moments: `lab=star|shop|fork|items|last`. Its rules modules are in the deploy file list above (the UI files stay client-only). Play it locally: `#/table?g=starchat&n=4` (`&opts=quick`, `&steps=200` to fast-forward, `&mini=catch|bun|count&lab=mini` to jump to a minigame, `lab=results` for its reveal).

Minigames (`minis/`): the interface is at the top of `minis/count.js` (turn games add `whose` / `act` / `timeoutMove`, see `bun.js`). Three kinds: `pick` (one secret entry each: Firefly Count), `sim` (one replayed run each, the Chatterflies pattern: Wishfall Catch posts `{ log, score }`, the referee replays the integer-only sim and keeps its own score; bot runs follow from seed, seat and level so every client draws the same ghosts) and `turn` (short referee turns: Hot Bun, whose pop number stays in `secret`). `pub.mini.startAt` is the referee clock plus the intro and 3-2-1, and `delay()` sets the deadlines from it. The UI is one overlay, `minis/Stage.jsx` (intro card, countdown, play area, waiting for others, results), which the board UI mounts all game long; it draws nothing outside a minigame. A new minigame: its pure module in `minis/index.js`, its numbers in `data.js` MINIGAMES, its view (`how`, `Play`, `detail`, optional `Reveal`) in `minis/views.js`.
